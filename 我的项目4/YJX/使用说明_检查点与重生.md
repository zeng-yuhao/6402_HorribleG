# YJX：目标玩家的检查点与重生

当前目标工程仍使用组员原有的 `BP_FirstPersonPlayerController`、`BP_FirstPersonCharacter` 和 `BP_FirstPersonGameMode`。控制器上已增加 `BPC_PlayerStateManager` 与 `HPRespawnBridgeComponent`。首次控制 Pawn 时，桥接组件保存初始出生位置；进入新的 Checkpoint 时更新重生位置。死亡时销毁旧 Pawn，调用组员 GameMode 的 `RestartPlayerAtTransform` 生成原本的默认 Pawn，随后请求 `Normal` 状态。

关卡中使用 `/Game/YJX/Integration/BP_YJXCheckpointTrigger_Ready`，不要使用源工程的 `/Game/FirstPerson/Blueprints/Trigger/BP_CheckpointTrigger`：旧蓝图会 Cast 到源工程的 PlayerController，不能识别组员控制器。

在关卡中放置新 Checkpoint 蓝图：

1. 调整 `CheckpointZone / 检查点区域` 的 Box 大小。目的：决定触发范围。
2. 将 Actor 放在希望重生的位置附近，调整 `Spawn Height Offset / 重生高度偏移`（默认 100 cm）。目的：让新 Pawn 的胶囊体避开地面；若 Actor 已位于胶囊中心，可设为 0。
3. 保留 `Only First Activation / 仅首次激活` 勾选，或取消以允许反复更新同一检查点。目的：控制同一个检查点是否重复保存。Actor 不会被销毁。

死亡过场请使用 `/Game/CodexDelivery/Death/BP_DeathCutsceneTrigger_Ready`。`Death Sequence Actor / 死亡过场序列Actor` 未指定时，使用 `Fallback Duration / 备用时长` 后重生。新桥接组件仅在目标控制器没有 `RequestRespawn` 蓝图事件时提供后备重生，不改变源工程已有流程。

测试：Play / 运行 → 经过 Checkpoint → 走进死亡区域 → 等过场/备用时长结束。预期：旧角色被销毁、组员原本的 Character 在 Checkpoint 位置重新生成、Checkpoint Actor 留在关卡里。当前枪拾取对组员角色的适配仍另待处理。
