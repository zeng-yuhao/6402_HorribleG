# YJX 源工程迁移包（阶段 5.1：YYN 钥匙拾取修复）

本目录是 `Horror_PlayerSet` 的完整功能快照，来源为 UE 5.3 工程。`Project/Content` 保留原始资源的相对路径和引用，`Project/Config` 保留输入/游戏模式配置，`Project/Plugins/HorrorTriggerPack` 包含 C++ 源码及 UE 5.3 Win64 二进制，`Project/Horror_PlayerSet.uproject` 保留源工程设置。

主要功能：玩家状态管理、Checkpoint、死亡 Trigger 和重生、死亡过场、NPC 对话、任务 UI/F 提交、步枪作为钥匙及提交后销毁步枪。演示关卡和枪/第一人称依赖资源也包含在 `Project/Content` 中。

目标工程 `我的项目4` 是 UE 5.6。本包**不是**可直接复制到目标 `Content/YJX` 的资源：UE 资源包含 `/Game/...` 绝对引用，直接改变文件夹路径可能导致引用旧路径或错误的同名资源。应先把这个迁移包放在目标工程根目录的 `YJX` 文件夹，后续使用 UE 编辑器迁移资源并在目标工程中连接玩家逻辑。

同路径冲突共有 9 个，包括 `/Game/FirstPerson/Blueprints/BP_FirstPersonGameMode` 和 8 个 LevelPrototyping 资源。默认不覆盖组员资源。

`UE56/Plugins/HorrorTriggerPack` 是使用 Windows SDK 10.0.22621.0 和 .NET Framework SDK 4.8 完整构建的 UE 5.6 插件。编辑器、游戏开发版和 Shipping 版构建均成功。请只将这一版安装到 UE 5.6 目标工程的 `Plugins/HorrorTriggerPack`；`Project/Plugins/HorrorTriggerPack/Binaries` 是源工程的 UE 5.3 DLL，不能用于目标工程。

阶段 1 已整理隔离文件。阶段 2 已把 UE 5.6 插件安装到目标 `Plugins/HorrorTriggerPack`，并将 428 个不重名资源新增到目标 `Content`；9 个已有同路径文件均保留原样。插件三个原生类和 11 个关键蓝图均用不保存资源的 Python 命令只读加载成功。

阶段 3 已备份目标组员的 PlayerController、Character、GameMode 和 `.uproject` 至 `YJX/TargetBackups/before_state_integration`。先在 `/Game/YJX/Integration/BP_YJXPlayerController_StatePrototype` 上验证组件添加/编译成功，再给目标默认 `/Game/FirstPerson/Blueprints/BP_FirstPersonPlayerController` 添加了**一个** `BPC_PlayerStateManager`，编译保存并重新只读加载验证。组员 Character 和 GameMode 的校验值与备份一致。试验副本不是当前 GameMode 使用的控制器。
